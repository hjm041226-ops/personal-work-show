## 1. 通用约定

### 1.1 路径前缀

所有业务接口以 `/api/v1` 开头：

```
http://localhost:8080/api/v1/...
```

### 1.2 数据格式

- 请求与响应一律 `application/json; charset=utf-8`。
- **JSON 字段统一 camelCase**，与现有前端数据结构完全一致（前端第二轮接入时无需字段映射）。
- 时间字段统一 ISO 8601，如 `2024-06-01T10:30:00+08:00`（或 UTC + 客户端自行换算，二选一并在部署时固定）。

### 1.3 统一响应包裹

所有接口返回同一结构：

```json
{
  "code": 0,
  "message": "ok",
  "data": { }
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| code | int | `0` 表示成功；非 0 为业务错误码（见 §5） |
| message | string | 人类可读结果说明；**建议直接返回中文**，前端可原样提示用户 |
| data | object \| null | 业务数据；无数据或出错时为 `null` |

HTTP 状态码约定：

| HTTP | 场景 |
|---|---|
| 200 | 请求已被服务端处理（成功或可预期的业务失败都返回 200，成败以 body.code 为准） |
| 400 | 请求体不是合法 JSON、路径不存在等传输层问题 |
| 401 | 预留：需要认证（本应用暂不需要登录） |
| 500 | 未预期的服务端异常（此时 body 可能不完整，前端按网络错误兜底） |

### 1.4 分页约定（预留，当前可不启用）

作品列表支持**可选**分页参数：

| Query 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| limit | int | 不传返回全部 | 每页条数；建议后端上限 100 |
| offset | int | 0 | 跳过条数 |

分页时 data 结构为 `{ "list": [...], "total": n, "limit": n, "offset": n }`；不传分页参数时 `total` 返回匹配总数、`list` 返回全部。

> 当前作品量少，前端不会传分页参数，后端返回全量即可，但**请按上述结构返回**以兼容未来。

### 1.5 CORS

开发期前端域名 `http://127.0.0.1:5173` 需加入后端跨域白名单（或本地配置 dev 代理）。生产环境按部署域名收紧。

## 2. 数据模型

### 2.1 作品 Works（列表项 / 详情项）

后端建表字段建议（`works` 表）：

| 字段 | JSON 键 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| 主键 | `id` | string | ✅ | **语义化字符串 id**（当前为 slug 风格，如 `archispace`），直接用于前端路由 `/work/:id`，请勿使用自增数字 |
| 标题 | `title` | string | ✅ | 详情页大标题，形如 `ArchiSpace：空间建筑与 3D Web 查看器`（主名：副题） |
| 角标 | `badge` | string | ✅ | 首页卡片图片左上角胶囊文案，形如 `空间 3D • WebGL` |
| 平台分类 | `categoryKey` | string | ⭕ | 预留：`web` / `app` / `desktop` / `other`。首页「全部/Web/App/Desktop/Others」筛选为未来功能，本期可不返回 |
| 展示分类 | `category` | string | ✅ | 详情页面包屑后半段，形如 `建筑科技` |
| 一句话简介 | `summary` | string | ✅ | 首页卡片描述 |
| 详情引言 | `desc` | string | ✅ | 详情页大图上方引言段落 |
| 封面图 | `image` | string | ✅ | **可访问的完整 URL**（含域名/CDN），前端直接用于 `background-image` |
| 技术栈 | `tags` | string[] | ✅ | 形如 `["Next.js", "Three.js", "Tailwind CSS"]` |
| 运行状态标签 | `overlayLabel` | string | ⭕ | 详情页大图底部浮层左侧文案，形如 `WEBGL 引擎运行中 — 60 FPS`；无则不展示状态点 |
| 运行指标 | `stats` | array | ⭕ | 浮层右侧指标，形如 `[{"label":"多边形数","value":"142,890"},{"label":"绘制调用","value":"24"}]`；`label` 中文名、`value` 字符串 |
| 排序 | `sortOrder` | int | ⭕ | 列表排序权重，升序；缺省按 `createdAt` 倒序 |
| 创建时间 | `createdAt` | string | ⭕ | ISO 8601 |
| 更新时间 | `updatedAt` | string | ⭕ | ISO 8601 |

> `tags` / `stats` 建议直接存 JSON 列（如 PostgreSQL `jsonb`）并**原样透传**，前端不做二次加工。
> 如未来详情页需要多图轮播，可扩展 `images: string[]`，本期不涉及。

**列表项与详情项字段差异：**

- 列表项（首页卡片需要）：`id, badge, title, summary, tags, image`（`category` 可选）
- 详情项（详情页需要）：`id, badge, category, title, summary, desc, tags, image, overlayLabel, stats`

后端实现时两种取舍均可：
1. 同一模型，列表也返回全字段（数据量小，最简单）；
2. 列表精简字段 + 详情全字段（按上面差异裁剪，响应更小）。

### 2.2 联系表单 ContactMessage

后端接收并落库：

| 字段 | JSON 键 | 类型 | 必填 | 校验规则 |
|---|---|---|---|---|
| 姓名 | `name` | string | ✅ | 长度 1–50 |
| 邮箱 | `email` | string | ✅ | 合法邮箱格式 |
| 留言 | `message` | string | ✅ | 长度 1–2000 |

服务端补充字段（返回给前端或留库）：`id`、`createdAt`；可选记录来源 IP、UA 用于排查（不进接口响应）。

## 3. 接口清单

| # | 方法 | 路径 | 用途 | 前端接入点 |
|---|---|---|---|---|
| 1 | GET | `/api/v1/works` | 作品列表（首页卡片数据） | 首页 `api-request/fetchWorks` |
| 2 | GET | `/api/v1/works/{id}` | 作品详情 | 详情页 `api-request/getWorkDetail` |
| 3 | POST | `/api/v1/contact/messages` | 提交联系表单 | 联系页 `api-request/submitMessage` |
| 4 | GET | `/api/v1/works/categories` | （预留）分类列表 | 首页分类侧边栏未来动态化 |

> 注意路由注册顺序：`/api/v1/works/categories` 需先于 `/api/v1/works/{id}` 注册，避免 `categories` 被 `{id}` 吞掉。

### 3.1 获取作品列表

```
GET /api/v1/works
```

**Query 参数（全部可选）**

| 参数 | 类型 | 说明 |
|---|---|---|
| `categoryKey` | string | 预留：按平台分类过滤（`web/app/desktop/other`） |
| `keyword` | string | 预留：标题/简介/技术栈模糊搜索 |

**成功响应 `code=0`：**

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "list": [
      {
        "id": "archispace",
        "badge": "空间 3D • WebGL",
        "title": "ArchiSpace：空间建筑与 3D Web 查看器",
        "summary": "专为学生设计工作室打造的交互式浏览器端 3D 建筑浏览器，用于实时审查空间布局。",
        "tags": ["Next.js", "Three.js", "Tailwind CSS"],
        "image": "https://cdn.example.com/works/archispace.webp"

    ],
    "total": 4,

    "offset": 0
  }

```


## 4. 错误码表

| code | 含义 | 建议 message |
|---|---|---|
| 0 | 成功 | ok |
| 40000 | 通用请求错误（JSON 解析失败、类型错误等） | 按具体原因说明 |
| 40001 | 参数校验失败（业务字段不合法） | 指明具体字段与原因，如「邮箱格式不正确」 |
| 40400 | 资源不存在（通用） | 资源不存在 |
| 40401 | 作品不存在（id 未命中） | 作品不存在：{id} |
| 50000 | 服务器内部错误 | 服务器开小差了，请稍后再试 |
| 40100 | 未认证（预留，暂不使用） | 请先登录 |

约定：

- 新增错误码在 10000–59999 段内编号，避免与 HTTP 状态码语义混淆；
- `message` 面向用户，前端拿到非 0 的 code 时会直接用 `message` 做提示（第二轮接入时实现），请写中文、可读。

## 7. Go 后端实现建议（非约束）

以下仅作建议，最终以你的工程习惯为准：

- **选型**：`gin`（或 `echo`/标准库）+ `gorm`（或 `sqlc`）+ PostgreSQL（`tags`/`stats` 用 `jsonb` 原样透传最省事）。
- **目录分层**（示例）：

  ```
  cmd/server/main.go        # 启动、路由注册
  internal/handler/         # 参数绑定/校验、组装统一响应
  internal/service/         # 业务逻辑
  internal/repository/      # 数据访问
  internal/model/           # 结构体（JSON tag 与上表字段一一对应）
  internal/pkg/response/    # {code,message,data} 统一包装
  ```

- **统一响应封装示例**：

  ```go
  type Body struct {
      Code    int         `json:"code"`
      Message string      `json:"message"`
      Data    interface{} `json:"data"`
  }

  func OK(c *gin.Context, data interface{}) {
      c.JSON(http.StatusOK, Body{Code: 0, Message: "ok", Data: data})
  }

  func Fail(c *gin.Context, code int, message string) {
      c.JSON(http.StatusOK, Body{Code: code, Message: message, Data: nil}) // 业务错误固定 200
  }
  ```

- **模型 JSON tag 与前端键一致**：

  ```go
  type Works struct {
      ID           string        `json:"id" gorm:"primaryKey"`
      Title        string        `json:"title"`
      Badge        string        `json:"badge"`
      CategoryKey  string        `json:"categoryKey,omitempty"`
      Category     string        `json:"category"`
      Summary      string        `json:"summary"`
      Desc         string        `json:"desc"`
      Image        string        `json:"image"`
      Tags         []string      `json:"tags" gorm:"type:jsonb"`
      OverlayLabel string        `json:"overlayLabel,omitempty"`
      Stats        []WorkStat    `json:"stats,omitempty" gorm:"type:jsonb"`
      SortOrder    int           `json:"sortOrder,omitempty"`
      CreatedAt    time.Time     `json:"createdAt"`
      UpdatedAt    time.Time     `json:"updatedAt"`
  }
  ```

- **路由注册顺序**（Go 的 httprouter/gin 通配路由同样要注意）：

  ```go
  v1.GET("/works", handler.ListWorks)
  v1.GET("/works/categories", handler.ListCategories) // 先注册
  v1.GET("/works/:id", handler.GetWorkDetail)         // 后注册
  v1.POST("/contact/messages", handler.SubmitContactMessage)
  ```

- **CORS**：允许 `http://127.0.0.1:5173`（开发期），可配置化。
- **环境变量**：`PORT`、`DATABASE_DSN`、`ALLOW_ORIGINS` 等通过 env 注入。
