# 前端对接契约 · 个人作品展示站(公开站)

> 本文件由《整合接口契约》(`docs/整合接口契约.md`)拆分而来,仅面向**个人作品展示站(公开站)前端**;对接中若与整合契约冲突,以整合契约为准。
> 完整版与两份旧契约(《后端接口文档(个人作品网站)》《后端接口文档(后台管理系统)》)的关系见 `docs/整合接口契约.md`。本文档的路径、JSON 键名、错误码、code/message 均逐字摘自整合契约(其已与 Go 源码逐字核对),对接一律以本文档为准。

**一句话定位:** 本文档是个人作品展示站(公开站)前端的对接依据——通过 `baseURL = /api/v1` 匿名读取作品数据并提交联系表单,无需登录、无 token。

**共享数据背景:** 公开站与后台管理系统共用同一 Go 后端进程、同一张 `works` 表,后台管理系统的增删改会**即时**影响公开站(公开站仅展示 `status=published && published=true && 未软删` 的作品;后台删除后公开站立即不可见)。

---

## 1. 对接总览

| 项目 | 值 |
|---|---|
| baseURL | `/api/v1`(如 `GET {baseURL}/works` → `GET /api/v1/works`) |
| 鉴权 | 匿名,无需登录、不携带任何 token |
| 请求/响应 | UTF-8 JSON(`application/json; charset=utf-8`) |
| 错误语义 | 可预期业务失败 **HTTP 固定 200**,以 body 内 `code` 区分(见 §2.2 与 §4) |

| # | 方法 | 路径 | 说明 |
|---|---|---|---|
| P1 | GET | `/works` | 作品列表(只含已发布、可见作品) |
| P2 | GET | `/works/categories` | 公开分类字典(Web/App/Desktop/Others,静态返回) |
| P3 | GET | `/works/{id}` | 作品详情;不存在/未发布 → `code 40401` |
| P4 | POST | `/contact/messages` | 提交联系表单(name/email/message) |

## 2. 通用约定(公开组适用)

### 2.1 统一响应包裹

所有业务接口统一包裹:

```json
{ "code": 0, "message": "ok", "data": { } }
```

| 字段 | 类型 | 说明 |
|---|---|---|
| code | int | 0 成功;非 0 为业务错误码 |
| message | string | 人类可读说明,中文,可原样提示用户(个别接口携带自定义中文,如联系表单的 `留言已收到,感谢联系`) |
| data | object / array / null | 业务数据;失败时为 `null` |

### 2.2 错误语义(公开组:业务失败 HTTP 固定 200)

| 场景 | HTTP | body code | 说明 / message 示例 |
|---|---|---|---|
| 成功 | 200 | 0 | message `ok`(联系表单为 `留言已收到,感谢联系`) |
| 可预期业务失败(参数校验、作品不存在、限流) | **200** | `40001` / `40401` | 以 body `code` 区分,**不要按 HTTP 状态判断业务成败** |
| 请求体不是合法 JSON(仅 P4) | 400 | `40000` | `请求体不是合法 JSON`(传输层错误) |
| 未知路径(引擎级 NoRoute) | 404 | `40400` | `接口不存在` |
| 未预期服务端错误 | 500 | `50000` | `服务器开小差了,请稍后再试` |

典型失败示例(HTTP 仍是 200,勿当作网络错误):

```json
HTTP/1.1 200 OK
{ "code": 40401, "message": "作品不存在：PRJ-0001", "data": null }
```

> 公开组无"未认证"场景(匿名);旧文档预留的 `40100` 整合后不使用。

### 2.3 时间格式

- `createdAt` / `updatedAt`:**RFC3339 / UTC**(如 `2026-09-03T10:30:00Z`),带时区,前端直接 new Date() 解析即可。
- 公开站接口**不涉及 `date`**(作品完成日期 YYYY-MM-DD)概念,公开 JSON 中没有该键。

### 2.4 作品 ID

- 后端生成,格式 **`PRJ-xxxx` 序列号**(从 `PRJ-0001` 起递增补零;序号 ≥10000 自然扩位,如 `PRJ-10000`),类型为字符串。
- 前端公开路由 `/work/{id}` 直接使用该值(如 `/work/PRJ-0001`),**不要假设为 slug**(旧版 slug 如 archispace 已废弃)。

### 2.5 分类枚举与文案

- DB 存储 / 过滤用的枚举键:`web / app / desktop / others`(旧文档预留的 `other` 输入归一为 `others`)。
- 但公开 JSON 里的 `category` 键输出的是**中文展示分类**(如 `建筑科技`,独立存储于 DB `category_label` 列),为空时该键不返回。
- 按枚举过滤请用 P1 的 Query 参数 `categoryKey=web|app|desktop|others`,其值与 P2 字典返回的 `key` 一致。

| 枚举键 | P2 字典文案(公开站) |
|---|---|
| web | Web |
| app | App |
| desktop | Desktop |
| others | Others |

### 2.6 分页形状(offset 风格,可选分页)

```
GET /api/v1/works?limit=&offset=
data: { "list": [...], "total": n, "limit": n, "offset": n }
```

- `limit` 1–100(可选);**不传 limit 返回全部**,此时 `data.limit = 0`(0 表示未启用分页),`total` 为命中总数。
- `offset` ≥ 0,跳过条数(与 limit 配合)。
- 列表排序固定:`sort_order ASC, created_at DESC`(前端无需传排序参数)。
- 当前作品量少,建议不传分页参数一次取全量。

### 2.7 CORS

- CORS 由后端统一配置,前端**无需自行处理**;但前端部署的跨域来源必须在后端白名单内(后端环境变量 `ALLOWED_ORIGINS` 逗号分隔,可配 `*` 全放行;未配置时默认放行 `http://127.0.0.1:5173`、`http://localhost:5173`)。
- 后端放行方法 `GET,POST,PUT,PATCH,DELETE,OPTIONS`;允许请求头 `Authorization,Content-Type`;预检 OPTIONS 直接返回 HTTP 204。

### 2.8 works 字段说明(公开站视角)

**卡片列表行(P1 返回)需要的键:**

| 键 | 类型 | 说明 |
|---|---|---|
| id | string | 作品 ID,`PRJ-xxxx` |
| badge | string | 首页卡片角标(如 `空间 3D • WebGL`) |
| title | string | 作品名称 |
| summary | string | 一句话简介(首页卡片描述) |
| tags | string[] | 技术栈/标签数组,原样透传展示即可 |
| image | string | **封面图可访问 URL(即封面,与后台 `cover` 同源)**,直接用 `<img src>` |
| category | string(可选) | 中文展示分类(如 `建筑科技`),未配置时键不返回,前端取值需兼容缺键 |

**详情(P3 返回)在列表键之外额外含:**

| 键 | 说明 |
|---|---|
| category | 同上(中文展示分类,可选) |
| desc | **详情引言(纯文本段落)**,详情大图上方展示 |
| overlayLabel | 详情大图浮层标签(如 `WEBGL 引擎运行中 — 60 FPS`) |
| stats | 详情浮层运行指标数组,元素 `{label:string, value:string}`,原样透传 |
| createdAt / updatedAt | RFC3339 / UTC |

**关键提醒:**

- **image 即封面**(DB `cover` 列,公开键名映射为 `image`);前端不要用 `cover` 键。
- **desc 是详情引言(纯文本)**,不要把它当 Markdown 正文(后台 JSON 里的 `desc` 是 Markdown 正文,与公开站无关)。
- `tags` / `stats` **原样透传,不要加工**。
- 详情里空的可选键同样不返回(如 badge/category/summary/desc/overlayLabel/stats),前端需兼容缺键。

## 3. 接口详解

### P1. 获取作品列表 `GET /api/v1/works`

匿名。**只返回可见作品**(`status=published` 且 `published=true` 且未软删)。

Query 参数(全部可选):

| 参数 | 类型 | 说明 |
|---|---|---|
| limit | int | 1–100;不传返回全部(`data.limit=0` 表示未分页) |
| offset | int | ≥0,跳过条数(与 limit 配合) |
| keyword | string | ≤100 字符;模糊匹配 `title` / `summary` / tags |
| categoryKey | string | 分类枚举键过滤:`web / app / desktop / others`(与 P2 字典一致) |

成功响应示例(`code=0`):

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "list": [
      {
        "id": "PRJ-0001",
        "badge": "空间 3D • WebGL",
        "title": "ArchiSpace:空间建筑与 3D Web 查看器",
        "summary": "专为学生设计工作室打造的交互式浏览器端 3D 建筑浏览器,用于实时审查空间布局。",
        "tags": ["Next.js", "Three.js", "Tailwind CSS"],
        "image": "https://placehold.co/1920x1200/1f2937/f1f5f9?text=ArchiSpace",
        "category": "建筑科技"
      }
    ],
    "total": 4,
    "limit": 0,
    "offset": 0
  }
}
```

失败示例(参数校验失败,业务失败 HTTP 200):

```json
HTTP/1.1 200 OK
{ "code": 40001, "message": "参数不合法:limit 必须为 1–100 的正整数", "data": null }
```

其他参数错误消息:`参数不合法:offset 必须为非负整数`、`参数不合法:keyword 长度不能超过 100`。

**前端使用说明:** 首页 `onMounted` 拉取列表渲染卡片;`category` 键即中文展示分类,可直接展示;标签展示用 `tags`;封面用 `image`(不要用 `cover`)。当前作品量少,建议不传分页参数,一次取全量。

### P2. 获取分类字典 `GET /api/v1/works/categories`

匿名,静态返回(源码 `model.PublicCategoryList()`)。

成功响应示例(`data` 为**数组**,不是对象):

```json
{
  "code": 0,
  "message": "ok",
  "data": [
    { "key": "web", "label": "Web" },
    { "key": "app", "label": "App" },
    { "key": "desktop", "label": "Desktop" },
    { "key": "others", "label": "Others" }
  ]
}
```

**前端使用说明:** 首页「全部/Web/App/Desktop/Others」侧边栏可由此动态化;切换分类时把 `key` 传给 P1 的 `categoryKey`。(注:路由注册时 `/works/categories` 先于 `/works/{id}`,该静态路径不会被 `{id}` 吞掉。)

### P3. 获取作品详情 `GET /api/v1/works/{id}`

匿名。仅返回可见作品;**不存在、已软删、草稿、`published=false` 一律 `code 40401`**(不泄露未发布内容),且 HTTP 仍是 200。

成功响应示例(`code=0`):

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "id": "PRJ-0001",
    "badge": "空间 3D • WebGL",
    "category": "建筑科技",
    "title": "ArchiSpace:空间建筑与 3D Web 查看器",
    "summary": "专为学生设计工作室打造的交互式浏览器端 3D 建筑浏览器,用于实时审查空间布局。",
    "desc": "为建筑事务所搭建物理空间设计与浏览器渲染之间的桥梁,针对高性能浏览器计算与流畅交互进行了深度优化。",
    "tags": ["Next.js", "Three.js", "Tailwind CSS"],
    "image": "https://placehold.co/1920x1200/1f2937/f1f5f9?text=ArchiSpace",
    "overlayLabel": "WEBGL 引擎运行中 — 60 FPS",
    "stats": [
      { "label": "多边形数", "value": "142,890" },
      { "label": "绘制调用", "value": "24" }
    ],
    "createdAt": "2026-09-03T10:30:00Z",
    "updatedAt": "2026-09-03T10:30:00Z"
  }
}
```

失败示例(`message` 用全角冒号、拼上请求 id;HTTP 仍是 200):

```json
HTTP/1.1 200 OK
{ "code": 40401, "message": "作品不存在：PRJ-0001", "data": null }
```

**前端使用说明:** 收到 `code=40401` 时展示「未找到该作品」空态 + 返回按钮(详情页内置 UI);空态判断只看 body `code`,**勿依赖 HTTP 状态**——业务失败时 HTTP 仍是 200,不要按网络错误处理,也不要因 200 而误判成功。

### P4. 提交联系表单 `POST /api/v1/contact/messages`

匿名。`Content-Type: application/json`。

请求体:

```json
{ "name": "张三", "email": "zhangsan@example.com", "message": "想咨询一下 ArchiSpace 的合作事宜" }
```

校验规则(校验失败 → HTTP 200 + `code 40001`):

| 字段 | 规则 | 校验失败 message |
|---|---|---|
| name | trim 后 1–50 个字符 | `姓名长度需为 1–50 个字符` |
| email | 格式 `^[^@\s]+@[^@\s]+\.[^@\s]+$` | `请检查：邮箱格式不正确` |
| message | trim 后 1–2000 个字符 | `留言长度需为 1–2000 个字符` |

成功响应示例(`code=0`,自定义中文 message,`id` 为数字):

```json
{
  "code": 0,
  "message": "留言已收到,感谢联系",
  "data": { "id": 10086, "createdAt": "2026-09-03T12:00:00Z" }
}
```

失败示例(邮箱格式):

```json
HTTP/1.1 200 OK
{ "code": 40001, "message": "请检查：邮箱格式不正确", "data": null }
```

限流:同一 IP 每 60 秒窗口内最多 `CONTACT_RATE_LIMIT` 次(默认 5,进程内内存实现,重启清零)。超限:

```json
HTTP/1.1 200 OK
{ "code": 40001, "message": "提交过于频繁,请稍后再试", "data": null }
```

请求体不是合法 JSON(传输层,HTTP 400 + `code 40000`):

```json
HTTP/1.1 400 Bad Request
{ "code": 40000, "message": "请求体不是合法 JSON", "data": null }
```

**前端使用说明:** 表单校验通过后调用;成功时展示 `message` 原文(`留言已收到,感谢联系`);`code≠0` 时直接 toast 后端 `message`。提交前可先做同规则前端校验以省请求。

## 4. 错误码表与前端拦截器建议

### 4.1 公开组错误码表

| code | 含义 | 实际 message 示例 | HTTP |
|---|---|---|---|
| 0 | 成功 | ok(联系表单为 `留言已收到,感谢联系`) | 200 |
| 40000 | 传输层:JSON 解析失败等 | `请求体不是合法 JSON` | 400 |
| 40001 | 参数校验失败(含限流) | `姓名长度需为 1–50 个字符` / `参数不合法:limit 必须为 1–100 的正整数` / `提交过于频繁,请稍后再试` | 200 |
| 40400 | 资源不存在(通用,未知路径) | `接口不存在` | 404 |
| 40401 | 作品不存在 | `作品不存在：{id}` | 200 |
| 50000 | 服务器内部错误 | `服务器开小差了,请稍后再试` | 500 |

> 旧文档预留的 `40100`(未认证)整合后**不使用**:公开组匿名,无未认证场景。

### 4.2 前端拦截器建议(公开组)

- 统一在请求封装里检查 body `code`:`code === 0` 时取 `data` 使用;**`code !== 0` 时直接用 `message` 提示用户**(中文文案,可原样 toast),不要自己拼接文案。
- `code 40401`(HTTP 仍为 200):详情页特殊处理——展示「未找到该作品」空态 + 返回按钮;只判断 code,勿依赖 HTTP 状态。
- `code 40001`:toast `message`(表单校验 / 限流提示)。
- `code 40000`(HTTP 400)、`code 40400`(HTTP 404,路径不存在)、`code 50000`(HTTP 500,服务端错误):同样直接提示 `message` 即可。
- 本组无 401 场景,无需登录跳转逻辑。

## 5. 与旧契约《后端接口文档(个人作品网站)》的主要差异提醒

| # | 主题 | 旧文档 | 现行为(= 整合契约,以本文档为准) |
|---|---|---|---|
| 1 | 作品 ID | slug(如 archispace) | 后端生成的 **`PRJ-xxxx`**;公开路由 `/work/{id}` 直接用,不要假设 slug |
| 2 | 封面键名 | `image` | 仍是 `image`;**与后台 `cover` 同源**(同一 DB `cover` 列),公开侧勿用 `cover` 键 |
| 3 | 详情引言键 | `desc` | 仍是 `desc`(纯文本段落);注意与后台 `desc`(= Markdown 正文)语义不同,不要混用 |
| 4 | 展示分类 | 分类取值语义模糊 | 公开 JSON `category` 现在是**中文展示分类**(如 `建筑科技`,独立存于 `category_label`,后台键 `categoryLabel` 与之同源);按枚举过滤请用 P1 的 `categoryKey`(`other` 输入归一为 `others`) |
| 5 | 错误码语义 | 业务失败 HTTP 200 + 业务码 | **同旧版**:业务失败 HTTP 固定 200,以 `code` 区分(40001/40401/50000 等) |
| 6 | 时间格式 | 旧示例带 `+08:00` 时区 | 输出统一 **UTC RFC3339**(`…Z`) |

其余(分页形状、列表排序、CORS 等)以本文档及《整合接口契约》为准。
